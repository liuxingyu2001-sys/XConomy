# XConomy 说明文档

> 面向 Paper / Spigot 服务端的经济插件，代理端使用 Velocity，无需在代理端安装插件。

## 一、模块结构

| 模块 | 说明 |
| --- | --- |
| `XConomy-Core` | 核心逻辑：数据存储、同步、指令、语言等 |
| `XConomy-Bukkit` | Bukkit / Spigot 平台适配 |
| `XConomy-Paper` | Paper 平台适配（最终产物） |

> 已移除 Sponge 模块，以及 BungeeCord 代理插件消息通道（`xconomy:aca` / `xconomy:acb`）。
> 跨服同步统一改用 **Redis**，代理端无需安装任何插件。

## 二、构建

```bash
mvn clean package -DskipTests
```

产物：`XConomy-Paper/target/XConomy-Paper-<版本>.jar`

- 开发 / 自用可直接 `mvn clean package -Dlicense.enabled=false`
- 编译要求：JDK 8 及以上（构建环境 JDK 25 已验证通过），Maven 3.6+

## 三、配置说明

### 3.1 `config.yml`

| 配置项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `Settings.language` | 字符串 | `Chinese` | 语言，默认简体中文 |
| `Settings.hidden-in-baltop` | 布尔 | `false` | 拥有 `xconomy.admin.hidden` 权限的玩家加入时自动从排行榜隐藏 |
| `Settings.transaction-record` | 布尔 | `true` | 是否保存交易记录（仅 MySQL） |
| `Settings.offline-pay-transfer-tips` | 布尔 | `false` | 记录离线转账并在玩家登录时提示（需 MySQL 且开启交易记录） |
| `SyncData.enable` | 布尔 | `false` | 是否开启跨服数据同步 |
| `SyncData.channel-type` | 字符串 | `Redis` | 跨服通道，目前仅支持 `Redis` |
| `SyncData.sign` | 字符串 | `aa` | 服务器组标识，需同步的服务器保持一致 |
| `LiuChat.cross-server-pay-tips` | 布尔 | `true` | 是否优先通过 LiuChat 私密投递跨服转账提示 |
| `LiuChat.tip-only-online` | 布尔 | `true` | 仅在收款人确实在线于其他服务器时发送 |
| `LiuChat.pay-tip-format` | 字符串 | 见配置文件 | 提示格式，支持 `&` 颜色代码与占位符 |
| `WealthTax.enable` | 布尔 | `false` | 是否开启财富税自动扣税 |
| `WealthTax.server-id` | 字符串 | 空 | 本服唯一标识，用于和 `executor` 匹配 |
| `WealthTax.executor` | 字符串 | 空 | 仅该 `server-id` 的子服执行结算（建议填装有 Residence 的子服） |
| `WealthTax.effective-date` | 字符串 | 空 | 生效日期 `yyyy-MM-dd`，用于公告后的缓冲期 |
| `WealthTax.time` | 字符串 | `00:00` | 每日结算时间（服务器本地时间） |
| `WealthTax.threshold` | 数字 | `50000000` | 起征点 |
| `WealthTax.rate` | 数字 | `0.005` | 每日税率（`0.005` = 0.5%） |
| `WealthTax.basis` | 字符串 | `full` | `full` 对全部财富征税 / `excess` 仅对超出起征点部分征税 |
| `WealthTax.include-residence-bank` | 布尔 | `true` | 是否把 Residence 领地银行计入财富 |
| `WealthTax.broadcast` | 布尔 | `true` | 结算后是否全服公告 |
| `WealthTax.destroy` | 布尔 | `true` | `true` 税款销毁 / `false` 税款入账到 `account` |
| `WealthTax.account` | 字符串 | 空 | `destroy: false` 时的入账账户名 |

### 3.2 `database.yml`

| 配置项 | 说明 |
| --- | --- |
| `Settings.storage-type` | `SQLite` / `MySQL` / `MariaDB` |
| `Settings.usepool` | 是否使用连接池（需 `slf4j`，Java 11+） |
| `MySQL.*` | MySQL / MariaDB 连接信息 |
| `Redis.host` / `Redis.port` / `Redis.db-index` | Redis 连接信息，默认 `localhost:6379` 的 `db 1` |
| `Redis.auth.*` | Redis 认证信息（无密码留空） |

> XConomy 使用 `db-index` 指定的库与独立频道 `XConomy_Sync`，可与 LiuChat 共用同一 Redis，互不冲突。

## 四、功能说明

### 4.1 跨服务器转账提示

当收款玩家不在本服时，按以下优先级处理：

1. **优先 LiuChat 私密投递**：安装了 LiuChat 且启用 `LiuChat.cross-server-pay-tips` 时，调用其私密投递 API（`deliverPrivate`）把提示**只发给收款玩家**（目标在哪个子服都能收到）。
2. **回退内置 Redis 通道**：LiuChat 不可用或未接受时，若开启 `SyncData`（Redis），通过内置通道向目标服务器投递私密提示。

提示格式由 `LiuChat.pay-tip-format` 控制，占位符：

- `%player%` 付款人
- `%target%` 收款人
- `%amount%` 转账金额

离线期间的转账可通过 MySQL 交易记录，在玩家登录时再次提示（`Settings.offline-pay-transfer-tips: true`）。

### 4.2 排行榜屏蔽

- 玩家自助：`/baltop hide` 隐藏自己，`/baltop display` 恢复显示。权限 `xconomy.user.balancetop.hide`（默认所有玩家可用）。
- 管理员：`/baltop hide|display <玩家>`，权限 `xconomy.admin.balancetop`。
- 自动隐藏：拥有 `xconomy.admin.hidden` 权限的玩家，在 `Settings.hidden-in-baltop: true` 时加入服务器会自动隐藏（同时也会从 TAB 列表隐藏，该行为始终生效）。

### 4.3 跨服 TAB 补全

`/pay`、`/balance give|take|set`、`/paytoggle`、`/paypermission`、`/baltop hide|display`、`/xconomy deldata` 等指令的玩家名参数，会合并以下来源进行补全：

1. XConomy 自身的跨服在线名单（开启 `SyncData`(Redis) 时）；
2. 本服在线玩家；
3. LiuChat 提供的全网络在线玩家名单。

### 4.4 财富税（自动扣税）

按「玩家总财富」按日征税，用于回收通胀。默认关闭，需在 `config.yml` 中开启。

**计税口径**

- 玩家总财富 = 经济账户余额 + 该玩家名下**所有领地（Residence）银行余额**（含子领地）；
- 当总财富高于 `threshold` 时计税；`basis: full` 对全部财富征收，`excess` 只对超出起征点的部分征收；
- 单日税额 = 计税基数 × `rate`，四舍五入到与货币相同的小数位；
- **扣除顺序**：先扣经济账户，不足部分再从领地银行扣除。

**执行方式**

- 定时任务每 60 秒在异步线程检查一次是否到达结算时间；真正的扣款切回主线程执行（涉及 Residence 与事件）。
- 多台子服共用同一 MySQL，通过 `xconomy_tax` 表主键占位保证**一天只结算一次**；`xconomy_tax_record` 表逐人记录保证**中断续跑不重复扣款**。
- 建议设置 `server-id` / `executor`，把结算固定到装有 Residence 的子服，避免其它子服因读不到领地银行而漏算。
- 结算完成后清空本服缓存，并借助 Redis 同步把最新余额推送给其它子服。

**管理指令**

- `/wealthtax run`（别名 `wtax`，也支持 `/xconomy tax run`）：**立即结算**。忽略“是否开启”、结算时间与生效日期，但仍校验执行服，因此可在未开启时手动跑一次做测试；逐人记录保证不会重复扣款。
- `/wealthtax status`（也可 `/xconomy tax status`）：查看今日结算状态（日期、是否已结算、人数、金额）。

> 控制台可直接执行 `/wealthtax run`。前提：配置已存在 `WealthTax` 段（首次使用新版本启动后会自动写入，需重启一次生效）。

> 财富税只对 XConomy 经济账户与 Residence 银行生效；若需征缴其它插件（如物品资产），需要单独扩展。

## 五、Redis / MySQL 使用建议

- **数据存储**：多服共用同一 MySQL 数据库（`database.yml` 中 `storage-type: MySQL`）。
- **跨服同步**：`SyncData.enable: true` + `channel-type: Redis`，各服保持相同的 `sign`、MySQL 与 Redis 设置。
- **离线提示**：`transaction-record: true` + `offline-pay-transfer-tips: true`（依赖 MySQL）。
- **Redis 要求**：需存在 `slf4j` 依赖（Paper 自带）；Redis 不可用时会记录连接异常。

## 六、部署

1. 将 `XConomy-Paper-<版本>.jar` 放入各 Paper 子服的 `plugins/` 目录。
2. 首次启动后按需修改 `config.yml` 与 `database.yml`。
3. 多服同步时，确保所有子服的 `SyncData.sign`、MySQL、Redis 配置一致。
4. Velocity 代理端**无需**安装 XConomy。

### 2.27.1

- 修复：移除 `plugin.yml` 中对 `LiuChat` 的 `softdepend`。XConomy 通过反射调用 LiuChat，本就不需要声明依赖；在同时装有 PlotSquared 与 Residence 的服务器上，该声明会形成循环依赖导致服务端启动失败。
- 财富税：`/xconomy tax run` 仍会校验执行服，避免在未装 Residence 的子服手动结算导致领地银行漏算。
- 财富税：结算改为以玩家当前实际余额为准扣除，避免快照过期时扣成负数。
- 财富税：部分扣款失败时不再删除记录（仅当完全未扣到款才删除重试），避免重复扣税；每日审计数据改为累加而不是覆盖。
- 财富税：税款入账账户不存在时自动创建，入账失败只记录日志，不影响已完成的结算。
- Residence 桥接在失败后不再永久缓存失败状态（支持 Residence 晚于本插件加载）。
